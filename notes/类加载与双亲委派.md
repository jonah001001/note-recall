# 类加载与双亲委派模型
## 一、类加载机制
### 类的生命周期
+ 一个类从加载到卸载，共有**7**个阶段，按顺序分别是** 加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载 **
+ **验证+准备+解析合称“连接”。**

| 阶段 | 内容 | 备注 |
| --- | --- | --- |
| 加载 | 1.通过类的全限定名，获得它的二进制字节流<br/>2.把字节流转化为方法区中的运行时数据结构<br/>3.内存中生成一个Class对象，作为访问类的数据入口 | 二进制字节流不限来源，所以衍生了动态代理，热部署，网络加载类等方式。 |
| 验证 | 包括文件格式验证、元数据验证、字节码验证、符号引用验证。  确保字节流符合规范，不会危害JVM安全 | 因为加载阶段的字节流来源不确定，所以这里要验证 |
| 准备 | 为类的静态变量分配内存，并设置初始零值 | public static int a = 10, 这里赋值为0，不是10。<br/>例外：public static final int a = 10, **编译器阶段的常量**，在这个阶段直接赋值为10 |
| 解析 | 把常量池里面的符号引用替换为直接引用 |  |
| 初始化 | 执行<clinit>方法，给静态变量赋值，执行静态代码块 | public static int a = 10，这里a被赋值为10 |


### <clinit>与<init>
|  | 对象创建 | 类加载 |
| --- | --- | --- |
| 第一阶段: 给零值 | 初始化零值 | 准备阶段 |
| 第二阶段: 给真实值 | 执行构造方法<init> | 执行初始化<clinit> |


### 类加载器
加载阶段通过**类加载器（ClassLoader）**获得二进制字节流

类加载器有三层：

+ **启动类加载器（Bootstrap）: 加载JVM核心类库（JAVA_HOME/lib, 如rt.jar）。由C++实现，是JVM的一部分，在Java代码里拿他会得到null。**
+ **扩展类加载器（Extension）: 加载JAVA_HOME/lib/ext下的扩展类库**
+ **应用类加载器（Application）：也叫系统类加载器，加载classpath上的类，平时写的类一般由它加载。**
+ **用户自定义类加载器**

注： JDK 9 引入模块系统后,"扩展类加载器"被"平台类加载器(Platform ClassLoader)"取代  

## 二、双亲委派模型
### 工作过程
① 类加载器收到请求

② 不自己先加载，而是委派给父加载器

③ 父加载器继续往上委派，一直到顶层的启动类加载器

④ 只有父加载器反馈“我加载不了”（搜索范围没有），子加载器才尝试加载

### 双亲委派的好处
+ **避免类重复加载**：一个类只会被一个类加载器加载一次，父加载过了子不会再加载
+ **保护核心类库的安全**

注：**两个类"相等",前提是由同一个类加载器加载**。同一个 .class文件,被两个不同的类加载器加载,得到的两个 Class 对象**不相等**。  

### 打破双亲委派
+ **SPI机制**（如：JDBC）：java.sql 接口由启动类加载器加载，但MySQL驱动实现在classpath上，应该由应用类加载器加载，于是引入线程上下文加载器，让父加载器能反向借子加载器加载实现类。
+ **Tomcat：**每个web应用有一个独立的类加载器，可以实现应用间的隔离，还能让同一个库的不同版本共存。
+ **热部署/OSGI：**每个模块独立类加载器，实现类的热替换。

实现方式：重写ClassLoader的loadClass()方法，如果只是想自定义加载，不破坏双亲委派，重写findClass()方法即可。
