## 一、Redis为什么快？
+ **基于内存**——数据全在内存,读写比磁盘快几个数量级。这是**最根本**的原因
+ **高效的数据结构**—— SDS、跳表、listpack、dict,都是为高效操作设计的
+ **单线程模型**——避免了锁竞争和上下文切换
+ **IO 多路复用**——单线程就能高效处理海量并发连接

## 二、 单线程模型  
**处理命令的核心流程是单线程**——接收命令 → 执行命令 → 返回结果,这条主流程由一个线程完成  

**为什么核心流程用单线程?**

    1. **避免锁竞争**:命令串行执行,天然没有并发问题,**不需要加锁**——这也是为什么 Redis 命令大多是原子的
    2. **避免上下文切换开销**
    3. **实现简单**:不用考虑并发控制,代码简单、少 bug
    4. **CPU 通常不是 Redis 的瓶颈**:Redis 是内存操作,瓶颈一般在内存大小和网络 IO。**既然 CPU 不是瓶颈,多线程榨多核 CPU 的意义就不大**

## 三、IO多路复用
单线程怎么同时伺候成千上万个客户端连接?如果傻等一个连接的数据,别的连接全饿死。

**解法:IO 多路复用**——一个线程**同时监听多个连接**,由操作系统的多路复用机制(epoll 等)"盯着"所有连接,**哪个连接数据就绪了就通知 Redis 处理哪个**。Redis 线程不傻等,只处理"已就绪"的。

## 四、 Redis 6.0 的多线程  
** Redis 6.0 引入了多线程 **

+ **多线程只用于"网络 IO"**——读请求数据、写响应数据、协议解析
+ **命令的执行,仍然是单线程**——保留“无并发问题”的核心特性
